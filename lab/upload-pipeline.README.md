# Upload quarantine service

`createUploadService({root, clamdHost, clamdPort})` in `upload-service.mjs` wires the reusable store to a real ClamAV daemon. No synthetic clean scanner is installed in the lab. Configure an explicit trusted clamd TCP endpoint; INSTREAM has no authentication or encryption. Keep it on an isolated service network and configure ClamAV stream limits at least as high as the application's `maxBytes`.

The returned async API supports `stage({ownerId, bytes, mediaType})`, `scanAndPromote({id, ownerId})` and `get({id, ownerId})`. Derive `ownerId` from the authenticated server session, never request input. Owners are bounded ASCII letters, digits, underscores and hyphens. IDs and download filenames are generated by the server. Client filenames never select disk paths. Serve downloads as attachments with `nosniff` and a restrictive content type; a clean antivirus verdict does not establish HTML, SVG, script, macro or document safety.

Pending and rejected uploads cannot be read through the API. The scanner receives a private copy, and promotion uses a separate copy whose SHA-256 and size match the scanned identity. Publishing uses a no-overwrite filesystem link, followed by a metadata commit. Retrieval rechecks the bytes. A concurrent promotion returns `upload_busy`; retry after the first finishes. Completed verdicts persist across restart. A crash can leave an orphan or a lock: stop all users of the store and reconcile it offline; locks are never automatically stolen. This is crash-conservative local storage, not a replicated or fsync-backed durable database.

Run on a local filesystem supporting atomic hard links, directory creation and same-directory rename. The application process, scanner implementation, root directory, parent path and filesystem are trusted. Mode bits are best-effort on Windows. Same-user filesystem access is not an enforced isolation boundary, and direct local tampering can cause denial of service. Keep arbitrary callers and other workloads out of the store. A scanner timeout, unavailable engine, malformed response, malware verdict or content mismatch rejects the upload. No retry of rejected content occurs; stage a new upload after fixing a scanner outage.

Run synthetic unit tests from the repository root:

```sh
node --test reference/upload-pipeline.test.mjs reference/clamd-client.test.mjs
```

These tests use an explicitly named fake TCP server and scanner fixtures. Actual ClamAV validation is a separate environment check; unit tests do not claim it ran.
