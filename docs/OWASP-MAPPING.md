# OWASP mapping for developers

This guide connects the kit's examples, templates, and adoption guidance to selected OWASP requirements and risk categories. Use it to identify integration work and plan verification of your application. A related requirement is a review target, not a passed requirement.

The mapping is pinned to **OWASP ASVS 5.0.0** (published 30 May 2025) and **OWASP Top 10:2025**, checked against their official sources on 12 November 2026. Requirement identifiers use OWASP's versioned form, for example `v5.0.0-8.2.1`. The [ASVS release overview](https://asvs.owasp.org/), [pinned English requirements JSON](https://github.com/OWASP/ASVS/blob/v5.0.0/5.0/docs_en/OWASP_Application_Security_Verification_Standard_5.0.0_en.json), and [Top 10:2025](https://top10.owasp.org/2025/) are the reference sources.

This is a source-based cross-reference, not an OWASP certification, an ASVS assessment, achievement of an ASVS level, or a security guarantee. The Top 10 is an awareness document, not a complete verification checklist. Local checks and their environments are recorded separately in [VALIDATION.md](VALIDATION.md).

## Reading the status

- **Example**: executable behavior exists within the documented sample's boundaries. Product integration and verification remain necessary.
- **Template**: the kit generates or supplies configuration; deployment and target-specific verification remain necessary.
- **Guidance**: instructions describe work that the adopting application or operator must implement.
- **Unassessed**: this mapping does not establish an implemented control or a verification result.

Every row below is a **partial relationship**. It does not claim that the entire referenced requirement is satisfied.

## OWASP Top 10:2025 cross-reference

The associations below are this kit's interpretation of its features against OWASP's categories. They are not OWASP-endorsed coverage results. Category names and numbering belong to the [2025 edition](https://top10.owasp.org/2025/).

| Category | Relevant kit material | Boundary to address in the application |
| --- | --- | --- |
| [A01:2025 Broken Access Control](https://top10.owasp.org/2025/A01_2025-Broken_Access_Control/) | Scopes, server checks, revocation, synthetic ownership, and ingress restrictions. | Complete object/field/tenant policies, CSRF, and SSRF protection. The kit provides SSRF guidance but no general outbound URL defense. |
| [A02:2025 Security Misconfiguration](https://top10.owasp.org/2025/A02_2025-Security_Misconfiguration/) | Nginx, SSH, firewall, container templates, and release exclusions. | Verify effective target configuration, routes, certificates, permissions, and recovery. |
| [A03:2025 Software Supply Chain Failures](https://top10.owasp.org/2025/A03_2025-Software_Supply_Chain_Failures/) | Quarantine, inventory, image digests, and dated version reports. | Complete provenance, vulnerability management, build/repository integrity, and update policy. |
| [A04:2025 Cryptographic Failures](https://top10.owasp.org/2025/A04_2025-Cryptographic_Failures/) | Node cryptography, password KDF, AES-GCM, and TLS template. | Define data classification, key lifecycle, certificate trust, and recovery. |
| [A05:2025 Injection](https://top10.owasp.org/2025/A05_2025-Injection/) | Parameterized sample queries, restricted tool arguments, and CSP defense in depth. | Review application SQL, shell, HTML/DOM, templates, and other interpreters; CSP does not replace output encoding. |
| [A06:2025 Insecure Design](https://top10.owasp.org/2025/A06_2025-Insecure_Design/) | Explicit trust boundaries, ordered stages, exact-action grants, and retry contract. | Perform application threat modeling and abuse-case review; validate business-specific limits. |
| [A07:2025 Authentication Failures](https://top10.owasp.org/2025/A07_2025-Authentication_Failures/) | Password/TOTP flow, limits, expiry, and revocation. | Integrate enrollment, recovery, factor protection, browser sessions, and transport authentication. |
| [A08:2025 Software or Data Integrity Failures](https://top10.owasp.org/2025/A08_2025-Software_or_Data_Integrity_Failures/) | Signed internal requests, authenticated archives, digest-bound dependency decisions, and payload manifests. | Authenticate release/dependency provenance and protect the pipeline. A manifest alone is not a signature. |
| [A09:2025 Security Logging and Alerting Failures](https://top10.owasp.org/2025/A09_2025-Security_Logging_and_Alerting_Failures/) | Audit guidance and minimal ingress logs. | Implement and test security events, protected transport/storage, alerts, and response ownership. No complete logging/alerting subsystem is supplied. |
| [A10:2025 Mishandling of Exceptional Conditions](https://top10.owasp.org/2025/A10_2025-Mishandling_of_Exceptional_Conditions/) | Local rollback, synchronous adapter checks, bounded inputs, and preserved operation results. | Test dependency failures, timeouts, resource exhaustion, generic external errors, and unknown external outcomes. The core is not an application-wide exception handler. |

## Plan verification before adoption

Choose the ASVS requirements applicable to your complete application and its risk, then record each requirement's implementation owner, evidence, result, and exclusions. Start from the full [ASVS 5.0.0 release](https://github.com/OWASP/ASVS/tree/v5.0.0), not only this selected list.

In particular, assess browser cookies and CSRF, SSRF (`v5.0.0-1.3.6`), recovery and factor enrollment, HTTP/MCP/OAuth integration, application logging, data retention, and operational failure handling. These boundaries are described in the [security model](SECURITY-MODEL.md) and [core integration guide](../reference/README.md). A passing kit test does not establish the behavior of an untested application integration or deployed environment.
